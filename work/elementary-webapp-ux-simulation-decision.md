# Elementary Learner Interaction Simulation Decision

판정일: 2026-08-31
결론: `not-needed` — 새 게임·canvas·drag·3D 시뮬레이션을 추가하지 않는다.

## 학습 목표와 현재 상호작용

이 앱의 학습 목표는 같은 낱말이 문맥에 따라 달라지는 뜻을 주변 말로 찾아보고, 단서가 모자라면 판단을 유보하며, 모호한 문장을 더 분명하게 고치는 것이다. 필요한 행동은 다음 네 가지로 모두 DOM에 이미 있다.

| 학습 행동 | 현재 DOM 상호작용 | 유지 근거 |
|---|---|---|
| 문장 읽기·첫 생각 쓰기 | 실제 문장 텍스트와 `<textarea>` | 학생 생각을 자동 채점하지 않고 안전하게 기록함 |
| 단서 찾기 | `TokenButton` 버튼, `aria-pressed`, 최대 2개 | 누를 수 있는 말과 선택 상태를 키보드·터치로 확인함 |
| 뜻·필요 단서 판단 | radio card와 명시적 확인 버튼 | 하나의 판정값을 기존 evaluator/reducer로 전달함 |
| 문장 정비 | radio card, 완성 문장 미리보기, 복수 해법 | 여러 유효 문장을 비교하며 표현을 고침 |

중립 SVG `NeutralCrossroadsIllustration`은 정답을 보여 주지 않는 장식이다. 그림을 움직이거나 2D 게임으로 바꾸면 의미 중립성·텍스트 전용·권리 추적을 해치므로 현재 형태를 유지한다.

## 시뮬레이션이 필요하지 않은 이유

- 목표가 물리적 현상이나 공간 조작의 원인·결과를 몸으로 시험하는 과학 시뮬레이션이 아니다.
- 드래그나 게임 점수보다 문장을 읽고 말 단서를 선택하는 것이 학습 증거이며, 현재 버튼·radio·텍스트가 그 증거를 직접 남긴다.
- 학생 입력은 탭 안의 메모리 상태에만 머물러야 하며, 새 canvas·게임 엔진·외부 라이브러리를 추가할 이유가 없다.
- 모바일 375px, 200% 글자, 키보드, reduced-motion에서 단순 DOM 흐름이 가장 예측 가능하다.

## 개선으로 허용한 상호작용 보강

이번 범위에서는 시뮬레이션을 만들지 않고, 기존 DOM의 발견성을 높인다.

1. 미선택 token에 점선 밑줄을 보여 “눌러 볼 수 있는 말”임을 알린다.
2. 선택 token은 기존 체크·실선 밑줄·`aria-pressed=true`를 유지한다.
3. 단서 가리기 전 목적 문장을 보여 주어 숨긴 뒤의 판단 행동을 예측하게 한다.

## 검증 범위

- component test: token role/state와 도움말 description
- browser test: 375px·200%에서 점선 affordance, overflow 0, 실제 core·extension·all 흐름
- axe·키보드·DOM 의미 구조: 기존 계약 유지
- VoiceOver, TTS, 오디오·녹음: 구현·검증하지 않음

새 상호작용이 학습 목표를 대신하지 않고 기존 평가·기록 모델을 통과하는지 확인하는 것이 이 판정의 합격 기준이다.
