# Word Meaning Crossroads Initial UX/UI Audit

감사일: 2026-08-29
대상: `https://wbmaker2.github.io/word-meaning-crossroads/`
범위: 입구 → 첫 문맥 → 단서 → 뜻 → 비교 → 문장 정비 → 기록의 학습자 화면, CSS, 접근성 DOM, 개인정보 경계

## 조사 경계

- 저장소에는 `AGENTS.md`, `EDUCATION_DESIGN.md`, `design-system/MASTER.md`가 없었다. 제품 설계 문서와 구현 계획을 기준으로 삼았다.
- 초기 상태의 `git status --short`는 깨끗했다.
- `impeccable`, `ui-ux-pro-max`, `redesign-existing-projects` 지원 스킬은 현재 환경에서 제공되지 않아 호출하지 않았다. 따라서 이 문서는 직접 수행한 브라우저·코드 감사 기록이다.
- VoiceOver 실제 검증과 초등학생·교사 대면 검증은 실행하지 않았다.
- imagegen은 실행하지 않았다. 유일한 화면 자산은 정답을 암시하지 않는 inline SVG와 favicon이며, 사실·정체성·증거 자산을 자동 생성할 필요가 없다.

## 브라우저 관찰

### P1 — 입구의 첫 행동이 모바일 첫 화면에서 늦게 보임

- 근거: 375×812에서 `글자 크기`와 `줄 간격` fieldset가 목표 카드보다 먼저 세로로 쌓이고, 목표 안내·개인정보 안내 뒤에 첫 `기본 길 4개` 카드의 제목만 보인다.
- 학습 영향: 처음 온 어린이가 무엇을 먼저 눌러야 하는지 찾으려면 한 번 이상 긴 스크롤을 해야 한다. 설정은 유용하지만 첫 미션 선택보다 시각적 우선순위가 높다.
- 수정 제안: 공통 설정을 작은 상단 도구 묶음으로 압축하고, 입구 카드 안에서 목표 → 경로 선택 → 첫 CTA 순서가 먼저 드러나게 한다. 기존 라디오 accessible name과 상태는 유지한다.
- 수용 기준: 375×812에서 목표 제목, 목표 요약, 경로 제목, 첫 경로 CTA가 한 번의 자연스러운 스크롤 안에 보이며 가로 넘침이 없다.

### P1 — 활동 카드의 핵심 입력과 다음 행동이 긴 장식 여백 뒤에 있음

- 근거: 1280×900 첫 문맥 화면에서 중립 SVG 아래에 큰 수직 여백과 안내 패널이 이어져 textarea와 `단서 찾기`가 첫 viewport 밖으로 밀린다. 문장 정비 화면에서도 원문·해법 카드가 먼저 길게 보여 CTA가 아래에 놓인다.
- 학습 영향: 화면 제목을 읽은 뒤 해야 할 입력 행동을 즉시 찾기 어렵고, 모바일에서는 스크롤 부담이 더 커진다.
- 수정 제안: SVG의 최대 높이와 상하 여백을 토큰으로 제한하고 문장·입력·주요 CTA를 하나의 `action-zone`으로 묶는다. 정비 화면은 원문과 선택지 사이 설명을 짧게 유지한다.
- 수용 기준: 첫 문맥 화면에서 문장·예상 입력 레이블·CTA가 1280×900 안에 보이고, 375×812에서는 CTA까지 한 번의 짧은 스크롤로 도달한다.

### P2 — 공통 카드 위계가 화면마다 반복되지만 단계 표지가 약함

- 근거: 모든 화면이 같은 흰색 카드·청록 제목·주황 패널을 사용한다. `scene-kicker`는 존재하지만 진행 표시와 본문 행동 사이의 단계 관계가 작은 텍스트로만 전달된다.
- 학습 영향: 비교·정비처럼 구조가 바뀌는 단계에서 “지금 무엇을 결정하는가”를 다시 읽어야 한다.
- 수정 제안: kicker와 진행 표시를 같은 `stage-header` 시각 묶음으로 정리하고, 단계별 본문 패널에 동일한 테두리·간격 토큰을 사용한다. 새 용어를 학생 문구에 넣지 않는다.
- 수용 기준: 각 활동 카드에서 단계 표지 → 제목 → 설명 → 선택/입력 → 주요 CTA 순서가 DOM과 시각 모두 일관된다.

### P2 — 피드백·안내 패널의 시각적 상태 구분이 약함

- 근거: 개인정보 안내, 텍스트 전용 읽기 안내, 선택 미리보기, 정답·오답 피드백이 모두 연한 주황 또는 연한 청록 패널로 표시된다.
- 학습 영향: 어린이가 “읽을 안내”와 “내가 방금 한 선택의 결과”를 색만으로 구분하기 어렵다.
- 수정 제안: 정보 안내는 중립 표면, 선택 미리보기는 청록 왼쪽 선, 오류·회복은 아이콘·문자 라벨·고대비 테두리로 구분한다. 색 단독 의미는 사용하지 않는다.
- 수용 기준: 색을 보지 않아도 heading·문자 라벨·아이콘으로 안내/선택/오류 상태가 구분되고 axe serious/critical 위반이 없다.

### P2 — 결과 화면의 다음 행동이 상세 기록 뒤로 밀림

- 근거: `ExplorationRecordScreen`은 학습 목표와 요약을 먼저 두었지만, 긴 응답 기록과 세부 목록이 화면을 크게 늘린 뒤 하단에 다시 하기·입구·인쇄 버튼을 둔다.
- 학습 영향: 활동을 마친 어린이가 “다음에는 무엇을 할까?”와 다시 시작 조작을 찾기 어렵다.
- 수정 제안: 배운 것·해낸 것·다음에 해 볼 것을 compact summary로 유지하고, 결과 조작을 요약 바로 뒤에 배치한다. 상세 응답은 접지 않고 기록 증거로 남긴다.
- 수용 기준: 기록 제목·배운 것·다음 행동·다시 하기/입구/인쇄 조작이 상세 응답 목록보다 먼저 DOM에 있고, 인쇄 출력 순서는 기존 계약을 유지한다.

### P3 — 중립 SVG 자산은 교체 필요 없음

- 근거: `NeutralCrossroadsIllustration.tsx`의 SVG는 `aria-hidden="true"`, 텍스트·title·정답 의미가 없고, 8개 낱말에서 동일한 기하를 재사용한다. 1280px 렌더 크기에서도 선명하며 그림을 숨긴 E2E 경로가 존재한다.
- 판단: 학습 증거나 사실을 전달하지 않는 개념 장식이며, 자동 생성 이미지로 바꾸면 오히려 의미 중립성·권리 추적을 약화시킬 수 있다.
- 조치: 기존 SVG와 `public/favicon.svg`를 유지한다. 교체 없음 사유를 `work/education-webapp-redesign-assets.md`에 기록한다.

## 우선순위와 제외 범위

- P1 두 건은 구현 수용 기준으로 이동한다.
- P2 세 건은 공통 토큰·레이아웃·결과 카드 작업에 포함한다.
- P3 자산은 유지한다.
- 판정 함수, 콘텐츠, reducer, 개인정보 저장 경계, text-only 정책은 리디자인 대상이 아니다.
- VoiceOver, 실제 사람의 학습자 승인, HVC·배포 상태는 이 감사의 합격 근거가 아니다.

## 초기 감사 결론

현재 앱은 학습 흐름·안전·접근성 자동 계약은 안정적이지만, 첫 행동이 화면 아래로 밀리고 활동별 위계가 반복되는 문제가 있다. 따라서 상태 로직을 재작성하지 않고 입구·공통 셸·활동 카드의 시각적 압축과 단계 위계를 개선하는 범위가 안전하다.
